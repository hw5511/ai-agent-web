렉을 만드는 코딩을 원천 차단

캡(blur≤40px 같은 숫자 제한)이 아니라 단 하나의 법칙으로 성능 바닥을 잡았습니다. v7 외부 SEED CARD 강제 배정은 그대로 두고, 같은 프롬프트(도자기 공방·관측소·향수)에 무작위 시드를 배정해 4개를 생성했습니다. 특히 noc은 과거 22fps 렉을 냈던 "컬러필드/그라디언트" 기법이 무작위로 배정됐는데도 CPU 6배 스로틀에서 60fps가 나왔습니다.

THE LAW — 매 프레임 변하는 값은 transform·opacity만

CSS 애니메이션·rAF·scroll·mousemove가 바꾸는 모든 값이 이 둘이어야 한다. 나머지(top/left/width/filter/box-shadow/background…)를 매 프레임 바꾸면 Layout/Paint 재실행 = 렉.

THE TRAP — transform만 써도 안전하지 않다

filter:blur·backdrop-filter·큰 그림자·mix-blend가 걸린 레이어는 옮길 때마다 텍스처를 다시 그린다(re-paint). 큰 흐림은 정적으로, 부드러운 색은 정적 radial-gradient로.

근거: research/skills-sh/knowledge/perf-principle.md (web.dev · Chrome · csstriggers). 정적 탐지기 perfcheck.sh로 4개 모두 0 FAIL 확인.
