### 슬라이드 4 — 개념 ②: Vercel이란 무엇인가

- **유형**: 개념
- **goal**: Vercel을 "GitHub 푸시 → 자동 배포 + Vercel 함수 + 환경변수"의 3종 세트로 인지시킨다
- **핵심 토픽**:
  - GitHub 레포와 연결 → 푸시할 때마다 자동으로 진짜 사이트로 배포
  - **Vercel 함수**: 서버에서 도는 한 토막의 자바스크립트 (= API 키 안전하게 숨길 곳)
  - **환경변수**: 키 같은 비밀값을 Vercel 대시보드에 따로 저장 (코드엔 X)
  - Hobby 플랜 = 무료 (개인 학습용으로 충분)
- **시각 요소**:
  - 3분할 카드: [GitHub 자동 배포] [Vercel 함수] [환경변수 금고]
  - 흐름도: 내 PC → git push → GitHub → (자동) → Vercel → 진짜 사이트
  - "서버리스 = Vercel이 알아서 도는 함수" 한 줄 풀이
- **강사 노트**: "백엔드 만든다는 말이 아니에요. Vercel이 알아서 도는 작은 함수 하나 얹는 거. Claude Code가 다 짜줍니다."

### 슬라이드 5 — 개념 ③: Vercel 함수의 구조

- **유형**: 개념
- **goal**: "api/ 폴더 안 한 파일 = 한 주소" 규칙과, 왜 키가 안 새는지 원리를 이해한다
- **핵심 토픽**:
  - 프로젝트 루트에 `api/` 폴더 생성
  - 그 안의 파일 하나 = 호출 가능한 주소 하나 (예: `api/hello.js` → `/api/hello`)
  - 함수 안의 코드는 **Vercel 서버에서만** 돌고, 브라우저엔 결과만 옴
  - 그래서 함수 안의 `process.env.MY_KEY`는 브라우저가 절대 볼 수 없음
  - 페이지에선 그냥 `fetch('/api/hello')`로 호출
- **시각 요소**:
  - 폴더 트리 박스:
    ```
    my-site/
    ├─ index.html
    └─ api/
       ├─ hello.js     → /api/hello
       └─ weather.js   → /api/weather
    ```
  - 통신 다이어그램: [브라우저] —fetch→ [Vercel 함수(키 보유)] —API→ [외부 서비스]
- **강사 노트**: "외울 거: 'api 폴더에 파일 하나 = 주소 하나'. 이거 하나만 알면 끝."
