- **핵심 토픽**:

### 슬라이드 3 — 라이브러리란? (script 한 줄로 수천 줄을 빌려쓰기)
- **유형**: 개념
- **goal**: CDN 라이브러리 개념을 "이미 만들어진 기능 묶음 빌려오기"로 직관 이해한다.
- **핵심 토픽**:
  - 라이브러리 = 누군가가 미리 만들어 둔 기능 세트
  - HTML `<script src="...">` 한 줄 = 수천 줄 코드 통째로 가져오기
  - CDN: 전 세계 어디서나 빠르게 받아오는 "공용 창고"
  - 우리는 코드 안 짜고 "이름만" 알면 된다 → 나머지는 Claude Code가 사용법 적용
  - 오늘 빌릴 도구: GSAP + GSAP ScrollTrigger
- **시각 요소**:
  - 좌측: 자판기 메타포 다이어그램 (동전 = script 태그 / 음료수 = 기능)
  - 우측 코드 박스:
    ```html
    <script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.x/gsap.min.js"></script>
    <script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.x/ScrollTrigger.min.js"></script>
    ```
  - 하단 한 줄 요약: "이 두 줄이 = 애니메이션 엔진 통째로"
- **강사 노트**: 학생이 자주 묻는 "이거 다운로드해야 해요?"는 NO. 그냥 script 태그만 붙이면 끝이라고 강조.

### 슬라이드 4 — 수평 스크롤의 원리: pin + translateX
- **유형**: 개념
- **goal**: 세로 휠 입력이 어떻게 가로 움직임으로 변환되는지 그림으로 이해한다.
- **핵심 토픽**:
  - "pin" = 섹션을 화면에 잠시 고정시키기
  - 그 사이 사용자가 휠을 굴린 만큼 → 안쪽 컨테이너가 `translateX`로 좌측 이동
  - 즉, 세로 스크롤 → 가로 이동 (착시처럼 느껴짐)
  - scrub: 스크롤 위치와 애니메이션을 부드럽게 묶어주는 옵션
  - 어디 쓰나? 갤러리, 스텝 소개, 타임라인, 케이스 스터디
- **시각 요소**:
  - 단계 다이어그램 3컷
    1. 섹션이 화면 가운데에서 pin
    2. 휠을 굴리면 안쪽 카드 4장이 가로로 이동
    3. 마지막 카드 도착 → pin 해제 → 다음 섹션으로 진행
  - 우측 미니 표: 세로 입력 → 가로 출력 매핑 공식
- **강사 노트**: "마우스 휠 굴리는 건 똑같은데, 화면은 옆으로 흐른다"는 느낌이 핵심. 데모 사이트(애플 제품 페이지 등) 1초 미리보기.

### 슬라이드 5 — 텍스트 컬러 reveal의 원리: progress 0~1 매핑
- **유형**: 개념
- **goal**: 스크롤 진행률(0~1)을 어떤 수치(색·크기·위치)에든 연결할 수 있다는 사고를 익힌다.
- **핵심 토픽**:
  - ScrollTrigger는 트리거 구간 안에서 "progress 0 → 1" 값을 계속 알려준다
  - 이 숫자를 색(회색→검정), 크기, 위치, 투명도 등에 매핑하면 자동 reveal
  - 오늘은 회색(#bbbbbb) → 검정(#111111) 단계별 변화
  - 한 번 익히면 응용 무한: 글자 크기, 배경색, 카드 회전 등
- **시각 요소**:
  - 가로 슬라이더 그림: 0 ━━●━━ 1
  - 진행률 0 / 0.5 / 1 일 때 헤드라인 텍스트 색 비교 3컷
  - 매핑 함수 메타포: "스크롤 위치 → 색 변환기"
- **강사 노트**: 어렵게 보이지만 "진행률 숫자 한 개에 효과 한 개 묶기"라는 단순한 원리. 학생에게 "색 말고 글자 크기로도 가능해요?" 질문 유도.

### 슬라이드 6 — 실습 ①: 섹션 페이드인 (가장 쉬운 1줄 효과)
- **유형**: 실습
- **goal**: 4주차 페이지의 모든 섹션에 GSAP 페이드인 효과를 1번의 프롬프트로 추가한다.
- **핵심 토픽**:
  - 효과: 섹션이 화면에 들어올 때 아래에서 위로 떠오르며 등장
  - 사용 함수: `gsap.from()` + `ScrollTrigger`
  - 4주차 페이지를 그대로 베이스로 사용 (재활용)
  - Claude Code에 넣을 프롬프트 통째 제공
  - 결과 확인 포인트: 각 섹션이 스르륵 떠오르는지
- **시각 요소**:
  - 좌측 프롬프트 카드:
    > "페이지 각 섹션에 GSAP ScrollTrigger로 페이드인 효과 추가해줘. 아래에서 위로."
  - 우측: Before(딱딱한 등장) / After(부드러운 페이드인) GIF 자리표시
  - 하단 체크박스: GSAP CDN 2줄 들어갔는지 확인
- **강사 노트**: 학생 90%가 "어 진짜 이게 다야?"라고 함. 프롬프트 한 줄로 끝나는 마법 같은 순간 강조.

### 슬라이드 7 — 실습 ②: 작품 갤러리 수평 스크롤
- **유형**: 실습
- **goal**: 갤러리 섹션을 가로로 흐르는 시네마틱 카드 4장 레이아웃으로 바꾼다.
- **핵심 토픽**:
  - 효과: 갤러리 도착 → 섹션 pin → 휠 굴리면 카드 4장이 가로로 흘러감
  - 적용 위치: 4주차에 만든 작품 갤러리 섹션
  - 사용 옵션: `pin: true`, `scrub: 1`, `translateX`
  - 프롬프트 한 줄로 의도만 전달, Claude가 옵션 셋업
  - 흔한 함정: 카드 4장 가로 폭 합계가 화면보다 커야 함 → Claude가 자동 처리
- **시각 요소**:
  - 좌측 프롬프트 카드:
    > "작품 갤러리에 카드 4개가 가로로 흐르는 수평 스크롤 효과를 GSAP로 만들어줘."
  - 우측: 갤러리 4장이 가로로 이어진 와이어프레임
  - 하단 트러블슈팅 박스: 안 움직일 때 체크할 것 (CDN 로드 / 컨테이너 width)
- **강사 노트**: 가장 "와!" 소리 나오는 구간. 학생들이 휠을 굴리며 신기해할 시간을 30초 이상 확보.

## 부록: 자주 발생하는 문제 (강사 대응)

- **GSAP가 안 움직여요** → 1순위: CDN script 태그 2줄(core + ScrollTrigger)이 `<head>` 또는 `<body>` 끝에 있는지 확인
- **수평 스크롤 카드가 안 흘러요** → 갤러리 컨테이너 `width`가 화면 폭보다 커야 함 (Claude에 "카드 4장이 화면 폭을 넘게 가로로 배치해줘" 추가 프롬프트)
- **텍스트 색이 한 번에 변해요** → `scrub` 옵션 누락 가능성. "스크롤하면서 부드럽게 변하게 해줘" 후속 프롬프트
- **페이드인이 너무 빨라요/느려요** → `duration` 조정 요청 ("페이드인 속도를 좀 더 천천히")
