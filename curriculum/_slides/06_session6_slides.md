### 슬라이드 3 — 개념 ①: 마우스 트리거 3종 비교
- **유형**: 개념
- **goal**: hover / click / mousemove 세 트리거의 차이와 용도를 구분한다.
- **핵심 토픽**:
  - **hover**: 마우스가 요소 위로 올라갔을 때 (색 변화, 확대)
  - **click**: 한 번 눌렀을 때 (펼침, 토글)
  - **mousemove**: 커서가 움직이는 매 순간 (자석, 빛 추적)
  - 판단 기준: "상태가 2개면 hover/click, 좌표가 필요하면 mousemove"
- **시각 요소**:
  - 3열 비교 표: 트리거 / 발동 시점 / 대표 예시 / 비용(성능)
  - 각 트리거별 미니 시연 이미지 (버튼 색 변화 / 메뉴 펼침 / 커서 추적)
- **강사 노트**: 오늘 만들 3개 실습이 각각 어느 트리거에 속하는지 미리 짚어주기 (마그네틱·spotlight = mousemove, flip = hover).

### 슬라이드 4 — 개념 ②: CSS Transform vs JS 동적 제어
- **유형**: 개념
- **goal**: 같은 "움직임"이라도 CSS와 JS의 역할이 다름을 이해한다.
- **핵심 토픽**:
  - **CSS 담당**: hover 상태 전환, rotateY, scale — 정해진 결과
  - **JS 담당**: 실시간 좌표 계산, 거리 계산 — 변하는 입력값
  - 조합 패턴: "JS가 값을 구하고, CSS transform이 그린다"
  - 오늘의 매칭: Flip Card = CSS 단독 / 마그네틱·Spotlight = JS+CSS 조합
- **시각 요소**:
  - 좌우 비교 카드: 왼쪽 CSS(정적 분기) / 오른쪽 JS(연속 값)
  - 다이어그램: `mousemove → JS 좌표 계산 → CSS transform 적용`
- **강사 노트**: 학생에게 "Claude Code가 알아서 나누지만, 왜 그렇게 짜는지 감만 잡으면 됩니다." 안심시키기.

### 슬라이드 5 — 개념 ③: 좌표 추적의 원리 (e.clientX / e.clientY)
- **유형**: 개념
- **goal**: 마우스 좌표가 어떻게 숫자로 들어오는지 직관적으로 안다.
- **핵심 토픽**:
  - `e.clientX`, `e.clientY` = 화면 왼쪽 위(0,0) 기준 픽셀 좌표
  - 요소 기준 좌표 = `getBoundingClientRect()`로 요소 위치 빼주기
  - 거리 계산 = 피타고라스(√(dx² + dy²)) — 마그네틱 발동 범위 판단
  - "수식 외울 필요 없음, Claude Code가 짜준다. 우리는 흐름만 안다."
- **시각 요소**:
  - 좌표계 그림: 브라우저 화면 + (clientX, clientY) 점 + 요소 박스
  - 의사코드 박스:
    ```
    화면에서 마우스 좌표 가져옴 → 버튼 중심까지 거리 계산
    → 가까우면 버튼을 마우스 쪽으로 이동
    ```
- **강사 노트**: 수학 공포감 차단. "거리 = 피타고라스"만 직관으로 보여주고 곧장 실습으로.

### 슬라이드 6 — 실습 ①: 마그네틱 버튼 (mousemove + transform)
- **유형**: 실습
- **goal**: 마우스가 가까이 오면 살짝 당겨지는 "연락하기" 버튼을 만든다.
- **핵심 토픽**:
  - 적용 위치: 포트폴리오의 "연락하기" CTA 버튼
  - 동작: 일정 거리 이내에서 버튼이 마우스 방향으로 살짝 이동
  - 핵심 변수: 발동 반경(px), 끌림 강도(0~1)
  - 마우스가 멀어지면 원위치 복귀
- **시각 요소**:
  - 실습 프롬프트 박스:
    ```
    연락하기 버튼에 마그네틱 효과 추가해줘.
    마우스가 근처 오면 버튼이 마우스 방향으로 살짝 당겨지도록.
    ```
  - Before/After 비교 이미지 (정적 버튼 → 자석 버튼)
  - 동작 다이어그램: 마우스 → 거리 측정 → 버튼 이동
- **강사 노트**: 끌림 강도 0.3 정도가 자연스러움. 너무 강하면 어색함 — 학생이 직접 숫자 바꿔보게 유도.

### 슬라이드 7 — 실습 ②: Flip Card (CSS rotateY + perspective)
- **유형**: 실습
- **goal**: 작품 카드를 hover하면 3D로 뒤집혀 설명이 나오는 카드로 만든다.
- **핵심 토픽**:
  - 적용 위치: 포트폴리오 작품 갤러리의 각 카드
  - 앞면: 이미지 + 제목 / 뒷면: 한 줄 설명 + 링크
  - 핵심 CSS: `perspective`, `transform: rotateY(180deg)`, `backface-visibility: hidden`
  - 트리거: hover (JS 거의 불필요 → CSS 단독 패턴 사례)
- **시각 요소**:
  - 실습 프롬프트 박스:
    ```
    작품 카드를 Flip Card로 만들어줘.
    앞면 이미지+제목, 뒷면 설명. hover로 뒤집기.
    ```
  - 3D 뒤집기 단계 시퀀스 (0° → 90° → 180°)
  - 앞면/뒷면 레이아웃 예시 카드
- **강사 노트**: perspective 값(1000px 정도)이 자연스러운 입체감 핵심. 학생이 perspective를 0으로 줘보고 차이 체험하게 하면 좋음.

### 슬라이드 8 — 실습 ③: Spotlight Follow (radial-gradient 좌표 추적)
- **유형**: 실습
- **goal**: 다크 히어로 섹션에서 커서 주변만 환해지는 빛 효과를 만든다.
- **핵심 토픽**:
  - 적용 위치: 포트폴리오 히어로(첫 화면) 섹션, 다크 배경 전제
  - 동작: mousemove마다 radial-gradient 중심 좌표를 커서로 갱신
  - 핵심: `background: radial-gradient(circle at X Y, 밝은색, 어두운색)`
  - X, Y 값을 JS가 매 프레임 업데이트
- **시각 요소**:
  - 실습 프롬프트 박스:
    ```
    히어로 섹션에 마우스 따라다니는 빛 효과 추가해줘.
    다크 배경에서 커서 주변만 밝아지도록.
    ```
  - 비교 이미지: 다크 배경 단독 vs spotlight 적용
  - 좌표 → gradient 중심 매핑 다이어그램
- **강사 노트**: 빛 반경(예: 300px)과 밝기 차이로 분위기가 확 달라짐. "이거 하나로 사이트가 영화처럼 보여요" — wow 모먼트 마무리.
