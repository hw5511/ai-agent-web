### 슬라이드 3 — 개념 ①: 데이터를 '구조화'한다는 것

- **유형**: 개념
- **goal**: 흩어진 정보 vs 표 형태 정보의 차이를 시각으로 각인시킨다
- **핵심 토픽**:
  - 메모장에 줄글로 쓴 후기 vs 엑셀 표로 정리한 후기
  - "표로 만들면" 가능한 것: 검색 / 필터 / 정렬 / 개수 세기
  - 일상 사례: 카톡 친구 목록, 쇼핑몰 주문 내역, 유튜브 댓글
  - 핵심 용어: "행(row) = 하나의 데이터, 열(column) = 데이터의 종류"
  - 오늘의 비유: "엑셀 잘 짜는 사람 = 데이터 잘 다루는 사람"
- **시각 요소**:
  - 좌측: 메모장에 "홍길동 잘했어요, 김철수 별로, 이영희 최고!" 줄글
  - 우측: 같은 내용 표 (이름 | 메시지 | 별점)
  - 화살표 가운데에 "구조화" 라벨
- **강사 노트**: "데이터를 표로 만들 수 있느냐가 곧 회원 시스템, 게시판, 쇼핑몰을 만들 수 있느냐와 같습니다."

### 슬라이드 4 — 개념 ②: 스키마 = 데이터의 설계도

- **유형**: 개념
- **goal**: '스키마'라는 용어를 친숙하게 만들고 컬럼 설계의 3요소(이름·타입·옵션)를 이해시킨다
- **핵심 토픽**:
  - 스키마 한 줄 정의: "표의 머리글을 미리 정해두는 것"
  - 컬럼 3요소: 이름(name) / 타입(텍스트·숫자·날짜) / 옵션(필수여부, 기본값)
  - 좋은 스키마 = 나중에 후회 안 함 (예: 날짜 빠뜨리면 정렬 불가)
  - 방명록 예시 스키마: id / name / message / created_at
  - "건축 도면" 비유: 짓기 전에 그려야 한다
- **시각 요소**:
  - 표 형태 다이어그램:
    | 컬럼명 | 타입 | 필수 | 예시 |
    |---|---|---|---|
    | id | 숫자 | 자동 | 1, 2, 3 |
    | name | 텍스트 | O | "우희" |
    | message | 텍스트 | O | "잘봤어요" |
    | created_at | 날짜 | 자동 | 2026-05-25 |
  - 도면 → 집 일러스트 비유 박스
- **강사 노트**: "이 표를 그릴 줄 알면 11주차 클라우드 DB로 그대로 옮겨갑니다. 오늘 그린 표 = 다음 주의 데이터베이스."

### 슬라이드 5 — 개념 ③: LocalStorage란? 브라우저의 작은 서랍

- **유형**: 개념
- **goal**: LocalStorage가 무엇이고, 어떤 한계가 있는지 5분 안에 직관적으로 이해시킨다
- **핵심 토픽**:
  - 한 줄 정의: "내 브라우저 안에 데이터를 저장해두는 작은 서랍"
  - 특징: 새로고침해도 남음 / 브라우저 닫아도 남음 / 5MB까지 저장 가능
  - 저장 방식: key(이름표) + value(내용) 한 쌍으로 보관
  - JSON.stringify / parse는 "표를 글자로 접었다 폈다" 하는 기술 (Claude가 다 처리)
  - 한계 미리보기: "내 컴퓨터에서만 보임 → 친구가 와도 안 보임" (8장 복선)
- **시각 요소**:
  - 브라우저 일러스트 안에 서랍 그림, 서랍 라벨에 "guestbook" key
  - 서랍 속에 카드들이 쌓여있는 모습
  - 우측 비교 미니표: LocalStorage vs 클라우드 DB (다음 주 예고)
- **강사 노트**: "오늘은 '내 컴퓨터 서랍'에 저장합니다. 다음 주는 '클라우드 서랍'으로 업그레이드해서 친구도 볼 수 있게 만듭니다."

### 슬라이드 7 — 실습 ②: 폼 만들고 LocalStorage에 저장하기 (30분)

- **유형**: 실습
- **goal**: 방명록 폼을 만들고 입력 → 저장 → 화면 카드 표시까지 한 흐름을 완성한다
- **핵심 토픽**:
  - 작업 흐름: 폼 추가 → 저장 버튼 → LocalStorage 저장 → 카드 목록 렌더링
  - 새로고침 테스트: F5 눌러도 카드가 그대로 있어야 성공
  - 디버깅 팁: 브라우저 개발자도구 → Application 탭 → Local Storage 직접 확인
  - 잘 안 풀릴 때: "방금 코드에서 저장이 안 돼. Local Storage가 비어있어." 라고 그대로 전달
  - 산출물: 폼 + 카드 목록이 보이는 페이지
- **시각 요소**:
  - 추천 프롬프트 박스:
    ```
    방명록 폼(이름·메시지)을 만들고
    입력하면 LocalStorage에 저장 후
    화면에 카드로 표시해줘.
    ```
  - 폼 → 화살표 → 서랍(LocalStorage) → 화살표 → 카드 목록 3단 다이어그램
  - 개발자도구 캡처 미니 (Application 탭 위치 표시)
- **강사 노트**: "F5 눌러서 안 사라지는 순간 학생들이 환호합니다. 그 감동 포인트를 꼭 강조하세요."

### 슬라이드 8 — 실습 ③: 항목 삭제·수정 기능 추가 (20분)

- **유형**: 실습
- **goal**: 저장된 카드에 삭제 버튼을 달고, LocalStorage와 화면이 동기화되도록 만든다
- **핵심 토픽**:
  - 작업 흐름: 카드마다 삭제 버튼 → 클릭 시 서랍에서도 제거 → 화면도 새로 그림
  - 핵심 개념: "화면에서만 지우면 새로고침 시 다시 나타남" → 서랍도 같이 지워야 함
  - 보너스: 수정 버튼 추가 (시간 남는 학생만)
  - 자주 발생: 한 개 지우려 했는데 다 지워짐 → "index로 한 개만 지워줘" 보강 프롬프트
  - 산출물: 추가/삭제가 가능한 완성형 방명록
- **시각 요소**:
  - 추천 프롬프트 박스:
    ```
    각 방명록 카드에 삭제 버튼 추가해줘.
    누르면 LocalStorage에서도 사라지도록.
    ```
  - 카드 일러스트 우상단 X 버튼 클로즈업
  - "화면 = 서랍" 양방향 화살표 다이어그램
- **강사 노트**: "여기서 '데이터의 일관성'이라는 큰 개념이 자연스럽게 등장합니다. 깊게 설명하지 말고 '둘 다 같이 지워야 한다'만 강조."

### 슬라이드 9 — 핵심 정리 & 다음 주 예고: 내 컴퓨터를 넘어서

- **유형**: 정리
- **goal**: 오늘 배운 3가지를 복기하고, LocalStorage의 한계를 통해 다음 주 클라우드 DB의 필요성을 자연스럽게 연결한다
- **핵심 토픽**:
  - 오늘의 3줄 요약:
    1. 데이터는 '표'로 설계한다 (스키마)
    2. 브라우저 서랍에 저장할 수 있다 (LocalStorage)
    3. 화면과 저장소는 항상 같이 움직인다
  - LocalStorage의 솔직한 한계:
    - "내 컴퓨터·내 브라우저에서만 보임"
    - 친구가 내 페이지에 방명록 남겨도 → 친구 컴퓨터에만 저장됨
    - 휴대폰에서 본 데이터는 PC에서 안 보임
  - 다음 주 예고 (11주차): **Vercel을 활용한 DB·API 연동** — 친구가 남긴 글이 내 화면에도 보이게!
  - 숙제: 오늘 만든 방명록을 친구한테 링크로 보내고 "어, 내 글이 너한테 안 보이네?" 직접 체험해오기
- **시각 요소**:
  - 좌측: 오늘 3줄 요약 체크리스트(다 채워진 상태)
  - 우측: 비교 표
    | | LocalStorage (오늘) | 클라우드 DB (다음 주) |
    |---|---|---|
    | 어디 저장? | 내 브라우저 | 인터넷 너머 |
    | 친구도 보임? | X | O |
    | 진짜 사이트? | 연습용 | O |
  - 하단: 11주차 티저 — "회원 시스템·진짜 사이트로 배포의 첫 발"
- **강사 노트**: "오늘의 결과물에 만족하되, '한계'를 꼭 느끼게 해서 다음 주 동기를 만드세요. 숙제는 강력 추천 — 직접 답답함을 겪고 와야 다음 주가 짜릿합니다."
