# 작업 의뢰서 — 16회차 슬라이드 SVG 일괄 생성

> **수신**: SVG 슬라이드 생성을 맡을 AI(Claude Code / Cursor / 기타)
> **발신**: 408 AI Agent Web 강의 커리큘럼 운영자
> **목적**: 16주 커리큘럼 전체 슬라이드 SVG를 동일한 스타일로 만들어 `assets/basic/stepXX/`에 배치하고, 강의장에서 바로 사용 가능한 상태로 만든다.

---

## 1. 프로젝트 컨텍스트

### 레포·작업 위치
- **GitHub**: https://github.com/hw5511/ai-agent-web
- **로컬 클론 후** `assets/basic/step09/` ~ `step16/` 디렉터리에 신규 SVG 생성 (없으면 mkdir)
- **기존 SVG**: `assets/basic/step01/` ~ `step08/` 67장이 이미 존재 — **시각 참고용 정답지**로 활용

### 강의 대상자
- 코딩 zero (HTML/CSS/JS 처음)
- Claude Code 사용은 익숙 (하네스·프롬프트 엔지니어링 알고 있음)
- 1회차당 2시간, 16주 코스

### 핵심 제약
- "백엔드" 표현 금지 → "Vercel 함수 / DB 연동" 으로 우회 (회차 .md의 표현 가이드 섹션 참고)
- 슬라이드에 학생을 위협하는 단어 X (예: "프로덕션", "API 라우트" 같은 추상어 X)

## 2. 입력 자료 (필독 순서)

### (A) 스타일 가이드 — 반드시 정독
```
curriculum/_design/svg_style_guide.md   (320줄, 색·폰트·레이아웃·6대 시그니처)
```
이 가이드는 step01~08의 67장 SVG를 정밀 분석한 결과. **모든 신규 SVG는 이 가이드의 토큰·레이아웃·시그니처를 따라야 함.**

### (B) 회차별 슬라이드 목차 — 슬라이드 1:1 매핑의 SOT
```
curriculum/_slides/01_session1_slides.md   ~   16_session16_slides.md
```
각 파일은 한 회차의 슬라이드 개요. 슬라이드별 제목·goal·topics·practice 프롬프트가 표로 정리됨. **이 표의 한 행 = SVG 한 장**.

### (C) 회차 마스터 .md — 맥락 보강
```
curriculum/01_session1.md   ~   16_session16.md
```
필요시 회차 전체 흐름·표현 가이드·1개념·누적 위치 확인.

### (D) 시각 참고용 정답지
```
assets/basic/step01/   ~   step08/
```
67장. 처음 5장 정도는 반드시 브라우저에서 열어 톤을 체득한 뒤 작업 시작.

## 3. 작업 범위·우선순위

### Tier 1 (필수, 신규 작성)
| 회차 | 디렉터리 | 슬라이드 수 | 1개념 |
|---|---|---|---|
| 9 | `assets/basic/step09/` | 8 | API 연동 (fetch) |
| 10 | `assets/basic/step10/` | 8 | 데이터 구조화 + 저장 |
| 11 | `assets/basic/step11/` | 8 | 클라우드 DB 연결 (Supabase) |
| 12 | `assets/basic/step12/` | 8 | 사용자 인증 (회원가입·로그인) |
| 13 | `assets/basic/step13/` | 8 | 내 도메인 가지기 |
| 14 | `assets/basic/step14/` | 8 | Vercel 환경으로 옮기기 |
| 15 | `assets/basic/step15/` | 8 | 보호된 API 호출 (AI 기능) |
| 16 | `assets/basic/step16/` | **12** | 결제 (토스 PG) + 캡스톤 발표 |

총 **76장** 신규.

### Tier 2 (재검토, 선택)
1~8회차는 이미 있지만 누락이 있을 수 있음 — 회차별 슬라이드 목차 .md와 실제 폴더를 대조해 빠진 슬라이드만 보완. **기존 SVG를 임의로 덮어쓰지 말 것.**

### 파일명 규칙
- 회차 .md의 표에 명시된 파일명을 **글자 그대로** 사용 (한글·언더스코어·확장자 포함)
- 예: `step09/01_오늘의_목표.svg`, `step16/12_수료.svg`
- 파일명에 em dash(`—`) 또는 특수문자 등장 시 회차 .md와 100% 일치시킬 것 (URL 인코딩은 브라우저 처리)

## 4. 품질 기준 (체크리스트)

각 SVG는 다음을 모두 만족해야 함:

### 4.1 캔버스·헤더 (전 슬라이드 공통)
- [ ] `viewBox="0 0 1280 720"`
- [ ] 좌상단 `WEB 0X` 흑색 배지 (`x=60, y=44, 66×24, rx=12`)
- [ ] 실습 슬라이드는 `실습 N` 노랑 배지 추가 (x=144부터)
- [ ] 제목 `y=130, font-size=40, weight=700, color=#171717`
- [ ] 부제 `y=178, font-size=19, color=#6b7280`
- [ ] 구분선 `y=212, stroke=#e5e7eb`
- [ ] 본문 영역은 `y=240` 이하

### 4.2 시그니처 요소
- [ ] 하단 `y=670` 부근에 흑색 강조 배너 (`#171717`, rx=10~12) — "오늘의 한 줄 메시지"
- [ ] 시스템 폰트만 (`-apple-system,BlinkMacSystemFont,'Segoe UI',Arial,sans-serif`)
- [ ] 코드는 `'Courier New', monospace`, 다크 배경 `#0f172a`, 텍스트 `#a3e635`
- [ ] `filter`·`shadow`·외부 폰트 로드 0 (색·테두리만으로 깊이)
- [ ] 카테고리 색상은 한 슬라이드에 최대 3~4개

### 4.3 색상 패밀리
- 노랑(HTML/실습), 파랑(CSS/개념/Claude 지시문), 초록(JS/연습), 분홍·보라(특수), 빨강(나쁜 예)
- 9~16회차 신규 주제는 **파랑 패밀리** 기본으로 (개념·데이터·API)
- "오늘의 목표" 카드는 **노랑→파랑→초록** 순서
- 정확한 hex는 `svg_style_guide.md` §2 표 참고

### 4.4 표현 가이드 준수
- 회차 .md의 **`## 표현 가이드 ⚠️`** 섹션을 슬라이드 문구에 반영
- 예: 13~16회차에서 "백엔드" 단어 사용 0건

### 4.5 검수 가능성
- 브라우저에서 직접 열었을 때 텍스트 잘림·요소 겹침 0
- 한글이 깨지지 않음 (시스템 폰트 사용 + UTF-8 저장)

## 5. 작업 순서 (권장)

1. **(30분)** `svg_style_guide.md` 정독 + `step01/` 5장 브라우저로 열어 톤 감각 익히기
2. **(30분)** 9회차 1장(`01_오늘의_목표.svg`)을 먼저 만들어 `step01/01_오늘의_목표.svg`와 시각 비교 → 톤 어긋남 보정
3. **(피드백)** 1장 시안을 운영자에게 보여 OK 받은 뒤 9회차 나머지 7장 진행
4. **(반복)** 9 → 10 → 11 → ... → 16 회차 순서로 작성
5. **(검수)** 각 회차 완료 시마다 `index.html`을 로컬 서버로 열어 해당 회차 슬라이드 16장 클릭 검수
   - 로컬 서버: `python -m http.server 8000` → http://localhost:8000
   - hash 라우팅: `#basic/9/1` ~ `#basic/16/12`

## 7. 모호하면 물어볼 것

다음 중 하나라도 막히면 **추측하지 말고** 운영자에게 질문:
- 슬라이드 목차 .md의 한 슬라이드가 정보가 부족해 시각화 방향을 정할 수 없을 때
- 표현 가이드와 슬라이드 목차 본문이 충돌할 때
- step01~08 톤과 의도적으로 달라야 하는 회차(예: 13회차 도메인은 가비아 로고 등장 등)가 있는지 불명확할 때

## 8. 참고 — 기존 8회차 슬라이드 카운트 이상 건
