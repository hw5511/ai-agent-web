# Sweep 프로토콜 — skills.sh 반복 dedup 크롤

> skills.sh를 "싹싹 긁어먹듯" 주기적으로 재조사한다. 핵심은 **이미 조사한 것은 거르고, 새 스킬만 찾아
> 내용 중복 여부를 판단해 새로운 지식만 적재**하는 것.

## 매 sweep 절차
1. **레지스트리 로드**: `INDEX.md`의 "조사 완료 목록"을 dedup 기준으로 읽는다.
2. **신규 탐색**: 조사 서브에이전트에게 다음을 지시한다.
   - skills.sh의 분야별 토픽 페이지 + "최근 추가/인기" 정렬 + 큐레이션 글을 훑어 **INDEX에 없는 스킬**을 수집.
   - `INDEX.md`의 "다음 sweep 후보 큐"를 우선 처리.
3. **중복 판단**: 새로 찾은 스킬마다
   - (a) INDEX에 이미 있으면 스킵.
   - (b) 이름은 새롭지만 **내용이 기존 지식과 사실상 동일**하면 → "중복(낮은 신규성)"으로만 INDEX에 기록, KNOWLEDGE_LOG에는 올리지 않음.
   - (c) **새롭고 유용한 지식**이면 → `knowledge/<분야>.md`에 추가 + `KNOWLEDGE_LOG.md`에 신규 항목으로 강조.
4. **레지스트리 갱신**: 이번에 본 스킬을 INDEX "조사 완료 목록"에 append, "후보 큐"·"커버리지 요약"·sweep 번호 갱신.
5. **커밋**: `research(skills-sh): sweep N — 신규 X종 / 신규지식 Y건` 형식으로 커밋.

## 신규성 판정 기준 (KNOWLEDGE_LOG 등재 여부)
- 이미 SPARK(v1/v2) 또는 기존 KNOWLEDGE_LOG에 있는 개념 → **등재 안 함**.
- 다음 중 하나면 **등재**: ① 검증 가능한 정량 규칙(수치/카운트) ② SPARK에 없는 새 메커니즘/프로세스
  ③ 기존 규칙을 실측치로 구체화 ④ 발견된 실험 버그를 막는 규칙.

## 종료 조건 (수렴)
- 한 sweep에서 **신규 유용 지식이 0~1건**이면 수렴으로 보고 빈도를 낮춘다(또는 종료).
- 분야별로 "후보 큐"가 비고 새 등록 스킬도 없으면 해당 분야 종료.

## 카덴스
- 선임연구원(메인)이 실증 실험 라운드 사이사이에 1 sweep씩 수동 실행하거나,
- `/loop`로 주기 실행(예: 기본 간격)하되, 각 tick이 위 절차를 그대로 수행하도록 한다.
- 현재 상태: **sweep 1 완료**. 다음은 sweep 2(후보 큐 우선).
